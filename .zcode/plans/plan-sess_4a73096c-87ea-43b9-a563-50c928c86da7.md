# 车机(Android 5.x-6.x)闪退全面加固

## Context
车机用户(多为 Android 5.x-6.x、armeabi-v7a、1-2GB 内存)反馈使用中/不定期闪退,且拿不到 logcat,目前完全无法定位。侦查结论:
1. **无可观测性**:崩溃只走 `react-native-exception-handler` → 异步 `appendFile`(原生崩溃时多半来不及写盘),原生 SIGSEGV/SIGABRT(QuickJS、ExoPlayer)不留任何现场;Java 层(UnsatisfiedLinkError、OOM)也没有崩溃落盘。
2. **Rust 层是地雷**:`RustBridgeKotlin.kt` 的 `object` 静态块 `System.loadLibrary`,失败抛 `Error`(所有 `catch (e: Exception)` 拦不住),且 Kotlin object 初始化失败会被永久毒化;`src/rust` JNI 导出无 `catch_unwind`,panic 即 abort;本地 jniLibs 只有 84MB 未 strip 的 arm64 调试 so,`src/rust/Cargo.toml` 无 release strip。
3. **CI 产物符号不匹配**:`release.yml` 编译的是 `rust-core`(符号 `com_lx_music_core_RustCoreBridge_*`,app 里没有任何 Kotlin 类声明),而 app 实际声明符号的是 `src/rust`(`cn_toside_music_mobile_RustBridge_*`);`auto-build.yml` 根本不编 rust。
4. **低内存适配缺失**:无 `largeHeap` 等。

## 改动

### 1. 崩溃现场留存(核心)
- 新增 `android/app/src/main/java/cn/toside/music/mobile/CrashSaver.kt`:在 `MainApplication.onCreate` 最先安装 default UncaughtExceptionHandler(链式转发),同步写 `filesDir/crash/crash-<时间戳>.txt`,内容:app 版本、`Build.MODEL/SDK_INT/SUPPORTED_ABIS`、`ActivityManager.MemoryInfo`(availMem/totalMem/lowMemory)、堆栈;保留最近 5 份。
- `src/utils/log.ts` 的 `initLogFile()`(src/core/init 前调用)启动时检测新崩溃文件,把内容并入 error.log(复用现有"设置-错误日志"展示与导出,错误日志 UI 位置实现时定位,复用 `getLogs` 模式)。
- `src/utils/errorHandle.ts` 的 native handler:补写设备信息头(与 CrashSaver 字段一致),尽力而为。

### 2. Rust 地雷修复
- `RustBridgeKotlin.kt`:懒加载改可恢复式(try/catch Throwable + `@Volatile var isAvailable`),失败不再永久毒化。
- `LXMusicCoreModule.kt`:全部 `catch (e: Exception)` → `catch (e: Throwable)`,失败 reject 明确错误码。
- `src/rust/src/jni_bridge.rs`:用宏给 ~30 个 JNI 导出套 `catch_unwind(AssertUnwindSafe)`,panic 时返回错误 JSON 而非 abort。
- `src/rust/Cargo.toml`:补 `[profile.release] strip = true、lto = true、codegen-units = 1`。

### 3. CI 产物一致性
- `.github/workflows/release.yml`:rust 编译目录 rust-core → `src/rust`(符号才与 app 匹配),4 targets `cargo ndk -t armeabi-v7a -t arm64-v8a -t x86 -t x86_64 -o ../android/app/src/main/jniLibs build --release`;注意 memory 基线里的 flate2/QRC 坑。
- `auto-build.yml` 对齐同样的编译步骤(两个发布渠道产物一致)。

### 4. 低内存适配
- `android/app/src/main/AndroidManifest.xml`:`<application>` 加 `android:largeHeap="true"`(对 Android 5/6 的 bitmap/Dalvik OOM 有效、无副作用)。
- `src/plugins/player/index.ts`:检查 `setupPlayer` 失败路径,加一次降级重试(去掉可选参数重试),失败仅记录不阻断启动。

### 明确不做
- 不动 QuickJS C 层、不动 ExoPlayer 具体参数、不删 rust 层(保持 fork 路线);桌面歌词等专项问题等拿到崩溃日志后对症处理。

## 验证
1. cargo:按 memory 工具链(vcvars bat + --offline)`cargo ndk` 4 targets 编 `src/rust` release,核对 so 体积(strip 后应 <10MB/ABI)。
2. `gradlew.bat assembleRelease`:出 4 个 per-ABI APK + universal,`unzip -l` 核对每个 APK 内 `liblx_music_core.so` 存在与大小。
3. eslint 通过;推 CI 分支用 gh 盯 workflow 通过。
4. 交付用户车机实测清单:装 v7a APK → 复现闪退 → "设置-错误日志"导出内容回传,按日志对症第二轮修复。
